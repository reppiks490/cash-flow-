# Hypothetical subscription scenario calculator

This offline, standard-library-only model computes illustrative HVAC subscription economics. It does **not** retrieve actual receipts, payments, customer counts, expenses, tax data or verified profit. All numbers are user-supplied assumptions, never financial evidence.

From the repository root, run `PYTHONPATH=products/revenue_recovery python -m unittest commercial.test_scenario_calculator -v` (Python 3.11+). For PowerShell set `$env:PYTHONPATH = "products/revenue_recovery"` first. For local scripts with the same Python path, import `Scenario` and `calculate_scenario` from `commercial.scenario_calculator`. Do not expose this function to a public endpoint or pass live customer data.

The function models `customers × (price − variable cost) − fixed cost − acquisition cost − refunds/fees`. It rounds up the minimum customer count required to reach the **pretax** target under constant assumed costs. If per-customer contribution is nonpositive, the target is unreachable under the model. The minimum-customer calculation assumes fixed refunds/fees and acquisition costs; it is not a forecast, break-even guarantee, or after-tax estimate.

A model may calculate a theoretical minimum exceeding its supported 10,000-customer input range. In that case, `minimum_customers_outside_supported_range=true` explicitly warns that the estimate cannot be evaluated within the supported scenario domain; it is **not** a viable customer-acquisition forecast. When a zero-dollar target and zero overhead are supplied, the theoretical minimum is 0 even if unit contribution is nonpositive. Both are planning-only arithmetic, not actual revenue or profit.\n\nThe output explicitly sets actual net profit and verified receipts to `null` because there is no connected financial source of truth. Before commercial release, replace hypothetical inputs with authenticated, reconciled private accounting evidence under separate approval; do not write receipts or personal data to GitHub. No billing, sending, CRM write or vendor integration is enabled by this calculator.

## Relationship to existing models

This module is an **optional scenario sensitivity** including separately assumed monthly acquisition expense and aggregate refunds/fees. The existing `commercial/economics.py` models per-customer processor fees and a fixed/variable cost decomposition; `commercial/measurement_guards.py` prevents modeled amounts from appearing as verified receipts. These are **alternative planning calculators**, not independent revenues or profit streams. Do **not** add their outputs together. Use explicit cost allocation to avoid double-counting owner labor, onboarding, provider charges, and acquisition fees. The commercial price and true service costs still require owner-approved discovery and source-backed validation; no outreach or billing is authorized by these tools.
